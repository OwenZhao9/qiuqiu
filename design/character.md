# 丘丘 · 形象规范

`character` 分支的输入。本文只定参数，不改 Emotion Ball 的任何文件。

对应 `docs/CONTRACTS.md` § 6。契约版本 **v0.1.2**。

## 1 · 形象来源

丘丘的视觉形象引用 [Emotion Ball](https://github.com/sam70361/aora-bot)，vendor 进仓库、不出网，按 `docs/ARCHITECTURE.md` § 3 引入四个脚本：

```html
<script src="vendor/emotion-ball/js/rings.js"></script>
<script src="vendor/emotion-ball/js/emotions.js"></script>
<script src="vendor/emotion-ball/js/ball.js"></script>
<script src="vendor/emotion-ball/js/engine.js"></script>
```

`i18n.js` 与 `app.js` 属于上游展示站，不引入。

- **身体形态**：`blob`（圆胖）。不用 `wedge`、不用 `gem`。
- **表情总数**：32 个，ID 分三段：`00–07` 生命周期 8 个、`10–21` 情绪反应 12 个、`30–41` 代理工作状态 12 个。丘丘只用这 32 个，不注册 `50+` 自定义表情。

### 剩下 9 个为什么不接

接一个表情要有一件**这个系统真的会发生的事**去触发它。硬凑触发条件的下场就是
待机甩彩带那一类——看着热闹，其实什么也没说。

| id | 名称 | 为什么不接 |
|---|---|---|
| `05` `06` `07` | 加载苏醒 / 休眠 / 抖动唤醒 | 睡与醒这条线上 `00` `01` `04` 已经三档齐了，再分三档没有对应的第四种闲置程度 |
| `15` | 疲惫 | 丘丘没有「累」这个量。按时间硬判（比如夜里就疲惫）是编的，不是测出来的 |
| `16` | 专注 | 「在专心做事」在本系统里就是 `30 思考中` 与 `35 等待输入`，没有第三种 |
| `17` | 慌张 | 出错已经归 `34`。再分一档就要判「多严重」，而错误载荷里没有这个字段 |
| `32` | 处理中忙碌 | 与 `30 思考中` 重叠。要区分只能按「等了多久」加计时器，那是新造一个状态 |
| `33` | 任务完成 | 写入成功已经归 `10 开心`。这一档还自带甩彩带与撒花，正是删掉的那套 |
| `36` | 联网加载 | 调模型这件事外面看到的就是「在想」，没有单独的联网阶段可报 |

### 身体的动静

表情引擎只换脸。**语音通话**时 `feedEnvelope(rms)` 把音量写进 `--qq-voice`，舞台跟着
脉动；**打字回复**没有音频，只换表情的话「正在说」和「待机」看着一模一样。所以宿主
把状态标在丘丘的挂载点上（`data-state`），三个状态各配一套身体动作：

| 状态 | 动作 | 参数 |
| --- | --- | --- |
| `speaking` | 一下一下点头，像嘴在动 | 0.44 s，下沉 2 px + 竖向压 0.975 |
| `thinking` | 慢慢左右晃，像在斟酌 | 2.4 s，±1.6° |
| `listening` | 起伏的呼吸，比待机明显一点 | 2 s，缩放 1 → 1.022 |

动作挂在引擎内层的 `.qq-ball` 上。`.qq-stage` 的 transform 归引擎（音量脉动），桌宠
最外层的 transform 归拖拽倾斜，三层各管各的，不会互相覆盖。桌宠这边状态是主窗口
镜像过来的（AD-5b），所以两个窗口的体态一致。

## 2 · 主题色与眼色

丘丘有两套形象（`CharacterLook`），共用同一套补丁算法，只是换调色板：

| look | 体色 | 眼色 | 用在哪 |
| --- | --- | --- | --- |
| `warm` | `#F2E7D3` 暖奶油 | `#2A2621` 暖墨 | 皮肤「素净」「卡哇伊」 |
| `anime` | `#FBE4EC` 樱色瓷白 | `#4E3A7A` 深堇紫 | 皮肤「二次元」，另加装扮层（§ 2.5） |

- `warm` 的眼色比引擎默认 `#1A1A1A` 略暖，与 `#F2E7D3` 的对比度 13.4:1
- `anime` 的眼色与体色对比度 8.9:1。二次元的眼睛不用纯黑——有色相才有「瞳」的感觉

两套在 200 px 与 120 px 下都够看。

### 为什么不走 `opts.color`

Emotion Ball 的 `EmotionBall.create(el, { color, eyeColor })` 会在**每一帧无条件**执行 `pose.body.color = theme.body`，覆盖表情自带的语义体色。这会同时废掉三处色彩表演：`21` 生气变红、`14` 害羞变粉、`34` 出错红白闪。丘丘用得上这三个，所以：

**不传 `opts.color`，也不传 `opts.eyeColor`。** 改为在启动时用公开 API `EmotionBall.config.register()` 打一遍主题补丁——纯数据配置，不触碰 vendor 文件，符合「只定参数」的约束。

### 主题补丁算法

`character` 在创建任何实例**之前**执行一次，全局生效：

```
对 32 个 id 逐个：
  raw = 深拷贝 EmotionBall.config.get(id).raw
  1. 体色：
     若 id 在下表 → raw.body.color = 下表里这套配色的值
     否则          → raw.body = { ...raw.body, color: 这套配色的体色 }
  2. 序列起始色：raw.sequence.frames 中所有 body.color 值
     等于 '#F3F0EA' / '#F6F3EC'（上游默认）或**任何一套配色的体色**的，
     一律替换为这套配色的体色
  3. 眼色：raw.eyes.both = { ...原来的 both（去掉 color）, color: 这套配色的眼色 }
     （applySpec 恒先应用 both 再应用 left/right，表情自带的左右差异不受影响）
  4. 彩带：删掉 raw.body 的 orbit / ribbons / confetti，
     并把 IDLE_ANTICS_OFF 里那几个的 raw.antics 置为 false
  EmotionBall.config.register(raw)
```

第 4 步是四刀砍三个来源，少砍一个就还看得见：

| 来源 | 上游用在哪 | 什么时候会冒出来 |
| --- | --- | --- |
| `antics` | `02` `04` `10` `19` | 待机随机自旋甩彩带 / 弹跳。`10 开心` 每写入一条记忆就会切一次，聊天全程都在甩 |
| `body.orbit` | `30 思考中` | 常驻的头顶环带。通话里「用户说完 → 丘丘开口」之间正是 `30`，每轮转一遍 |
| `body.ribbons` / `body.confetti` | `33 任务完成` | 进入表情时甩一次 / 撒一次 |

第 3 步安全的依据：32 个表情**没有任何一个**声明过眼色，全部落在引擎默认 `#1A1A1A` 上，所以摘掉 `color` 不会丢上游数据。

### 换形象时重打补丁：每一处都要无条件覆盖

`EmotionBall.config.get(id).raw` 拿到的是**上一次补丁的产物**，不是上游原文。所以第 2、3 步都不能写成「原来没有才补上」：

- 眼色若写成 `{ color: 新色, ...原来的 both }`，展开会把上一套的眼色盖回去，换形象换不动眼睛
- 序列起始色若只认上游那两个默认色，第二次换形象时 `fb.color` 已经是上一套的体色，就再也换不动了

判据是 `warm → anime → warm` 之后整个注册表必须与第一次 `warm` **逐字节相同**，`packages/character/test/look.test.ts` 守着这条。

## 2.5 · 二次元的装扮层

`anime` 除了换配色，还往引擎**运行时画出来的 SVG** 里插一层零件（`src/costume.ts`）。仍然不碰 `vendor/` 任何文件，摘掉之后 SVG 回到原样。

插的位置分三层，靠 z 序解决遮挡：

```
bodyG
  ├─ back   （空，留给以后加在身体之前的东西）
  ├─ head   （引擎的身体）
  ├─ mid    泽面高光 · 蝴蝶结 · 腮红   ← 压在身体上、眼睛下
  ├─ eyeL   （引擎的左眼）
  ├─ eyeR   （引擎的右眼）
  └─ front  眼高光                   ← 压在眼睛上
```

插在 `bodyG` **里面**而不是 SVG 根上，是为了白拿身体的整体变换：呼吸、点头、生气抖动都写在 `bodyG` 的 `transform` 上，当子节点就自动跟着动，一帧 JS 都不用跑。

### 跟着眼睛走的两件

丘丘的眼睛**不固定在脸上**，它在整个身体上游走（`02` 待机就在 `EXPRESSIONS[0]` 与 `[8]` 之间来回，一个在右上、一个在中左）。所以腮红不能钉死在「脸颊」——那会飘到没有脸的地方。做法是每帧读眼睛节点的 `transform`，它的形状固定是：

```
translate(ex ey) [rotate(r)] scale(sx sy) translate(-bx -by)
```

| 零件 | 抄哪一段 | 为什么 |
| --- | --- | --- |
| 眼高光 | 整条照抄 | 于是高光活在眼睛自己的局部坐标系里，眨眼、旋转、缩放全部白拿 |
| 腮红 | 只抄头一个 `translate`，往下偏 30 | 跟了 `scale` 的话，眨眼那一瞬间腮红会跟着压成一条线 |

眼高光另外**裁进眼睛自己的形状里**（`clipPath` 的 `d` 直接抄眼睛的 `d`）。丘丘的眼睛不是圆的，`02` 待机时是两根斜置的胶囊，别的表情有月牙、有横线；按固定偏移画的圆点在窄形状上必然探出去，看着像脸上粘了两粒白米。裁完剩下的是一牙月形高光，这正好是二次元画眼睛的画法。

每帧的开销是两次 `getAttribute` 加几次 `setAttribute`，不读布局，不触发重排。

### 丘丘的颜色不跟随明暗主题

界面换暗色主题时，丘丘的体色与眼色**不变**。丘丘是角色不是控件；暖奶油球体落在深色背景上是刻意的对比。`design/tokens.css` 把这两个值也导出成变量（`--qq-ball-body` / `--qq-ball-eye`），但明暗两套里取值相同。

## 3 · 尺寸与创建参数

| 场景 | 容器尺寸 | `eyeScale` | `lite` | `idle` | `autostart` |
|---|---|---|---|---|---|
| 桌宠窗口 | 200 × 200 px | `1` | `false` | 见 § 4 | `true` |
| 主窗口（左栏顶部） | 120 × 120 px | `1.5` | `true` | `false` | `true` |
| 网页端（页面内嵌） | 160 × 160 px | `1.2` | `false` | 见 § 4 | `true` |

- 容器是正方形 `div`，`width` 与 `height` 写死上表像素值，不用百分比。SVG 自适应容器。
- `eyeScale` 按上游建议取值：≤ 80 px 用 `1.5~1.8`，120 px 悬浮窗用 `1.5`。主窗口的 120 px 实例同时开 `lite: true` 关掉彩带与撒花——主窗口里丘丘是身份标识不是主角，特效会抢对话区的注意力。
- 三处实例共享同一个 rAF 心跳，多开不增加循环开销。
- 桌宠窗口与主窗口是两个渲染进程，各自持有一个实例；按 AD-5，桌宠实例的状态与表情全部来自 IPC `setPetState`，不自己连 SSE。
- 主窗口失去焦点或被最小化时对 120 px 实例调 `ball.setActive(false)`，恢复时 `setActive(true)`。网页端用 `IntersectionObserver`，丘丘滚出视口调 `setActive(false)`。桌宠实例常驻，不停帧。

创建示例（桌宠窗口）：

```js
applyQiuqiuTheme();                      // § 2 的主题补丁，全局只跑一次
const ball = EmotionBall.create(el, {
  emotion: '02',
  shape: 'blob',
  eyeScale: 1,
  lite: false,
  fallbackId: '02',
  idle: { standbyAfter: 90000, sleepAfter: 300000, standbyId: '04', sleepId: '00' }
});
```

## 4 · 闲置策略

「闲置」= 距离上一次**用户交互或状态切换**经过的时间。计时由引擎的 `_lastActivity` 维护，宿主可用公开方法 `ball.resetIdle()` 手动复位；`setEmotion(id)` 不带 `auto` 标记时也会自动复位。

| 阶段 | 阈值 | emotionId | 表现 |
|---|---|---|---|
| 活跃待机 | 0 – 90 s | `02` 待机放空 | 左看看右看看 |
| 待机 | 90 s | `04` 发呆 | 半闭眼慢轮换，双眼各望各的 |
| 睡眠 | 300 s | `00` 睡眠 | 眼睛闭成细线，右上角飘 zzz，不再注视鼠标 |

传给引擎就是 `idle: { standbyAfter: 90000, sleepAfter: 300000, standbyId: '04', sleepId: '00' }`。

**桌面端只有主窗口开 `idle`，桌宠传 `idle: false`。** 表情只能有一个来源（AD-5b）：桌宠自己推进闲置的话，它会照自己的计时器睡过去，而主窗口那只还醒着，两个窗口两张脸。闲置由主窗口驱动，经 `setPetState(state, emotionId)` 镜像给桌宠。

网页端没有桌宠，`web` 实例自己开 `idle`。

### 唤醒

当前表情是 `00` 时，任何一次会让状态机离开 `idle` 的事件（发送消息、按住说话、桌宠单击）走唤醒过场：

1. `ball.setEmotion('01')` —— 320 ms 切入，2100 ms 的睁眼序列，`settle: { next: '02' }` 由引擎自动落到 `02`
2. 唤醒序列播放期间**不阻塞业务**：`POST /chat` 照常发出，气泡照常出字
3. 序列结束（`change` 事件报出 `id === '02'`）后，状态机把当前状态的表情补上；若期间状态已经变成 `thinking`，直接切 `30`

当前表情是 `04` 时不走唤醒过场，直接切到目标状态的表情。

| 表情**引擎源代码与表情配置数据**（状态机、弹簧插值、球面投影、眼环/眼形参数、动画原语、关键帧序列） | 双许可：非商业免费；商业用途可向上游获取授权 | 引擎可以留下，但商业集成必须搭配自有或另行合法授权的角色形象 |

落到工程上的三条硬规矩：

1. vendor 目录保留上游的 `LICENSE`、`LICENSE-COMMERCIAL.md`、`NOTICE.md` 三个文件原文，不删不改。
2. 不修改 `vendor/emotion-ball/` 下的任何文件。所有定制只经 `EmotionBall.config.register()` 与 `EmotionBall.create()` 的选项完成——本文 § 2、§ 3 的做法都满足这条。
3. `character` 的表情映射表（状态 → id、事件 → id、情绪 → id）与本文的补丁表分别独立成模块，只依赖 `emotionId` 字符串。换形象时只需换一个渲染适配层，映射表原样复用。
