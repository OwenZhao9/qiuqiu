# 系统架构

八层，从用户看得见的到看不见的。每层写清楚：干什么、用什么、在哪个目录、哪个分支、谁负责。

## 分层总览

| # | 层 | 职责一句话 | 目录 | 分支 |
|---|---|---|---|---|
| 1 | 端 | 桌面常驻窗口 / 网页 | `apps/desktop` `apps/web` | `frontend` |
| 2 | 界面 | 丘丘表情 + 对话窗口 + 记忆事件侧栏 | `apps/web` `packages/character` | `frontend` `character` |
| 3 | 对话编排 | 拼 prompt · 调模型 · 分发回复 · 送去写入 | `services/api/orchestrator` | `backend` |
| 4 | 记忆中间件 | 筛选 · 压缩 · 合成 · 检索 · 冷热调度 · 性格沉淀 | `packages/memory` | `memory` |
| 5 | 存储 | 热 / 冷 LanceDB · SQLite · 磁盘文件 | `packages/data` | `data` |
| 6 | 模型 | Chat / Vision / ASR / VAD / TTS 统一适配 | `packages/models` | `models` |
| 7 | 人格 | 安全边界 · 预设 · 相处性格 · 当前人格合成 | `packages/memory/persona` | `memory` |
| 8 | 输入 | 主动经界面 · 被动直连中间件 | `services/api/ingest` | `backend` |

设计规范（视觉、交互、状态机、表情映射）在 `design/`，分支 `design`。

## 每层细说

### 1 · 端

两种形态共用同一形象与同一记忆。

**桌面端**：Electron 两个 BrowserWindow——桌宠窗口（透明、置顶、无边框、常驻）和主窗口（三栏）。托盘图标、全局快捷键唤起。两个窗口是两个渲染进程，经主进程 IPC 通信。

**网页端**：同一套 React 代码，单页面，免安装，移动端可访问。没有桌宠窗口，丘丘嵌在页面里。

### 2 · 界面

**丘丘**：形象与表情引擎引用自 [Emotion Ball](https://github.com/sam70361/aora-bot)，四个 JS 文件零依赖。角色状态机四态：闲置 / 听 / 想 / 说。两路输入驱动它：记忆事件（决定表情）、对话状态（决定状态机切换）。口型由语音合成的音量包络驱动。

**对话窗口 / 输入条**：用户主动输入的唯一入口。桌面端是桌宠气泡 + 内联输入条，网页端是对话窗口。流式显示回复，回复下方标「参考了 N 条记忆」。

**记忆事件侧栏**：实时滚动显示 filter / write / merge / recall 四类事件，每条带理由。被丢弃的打灰，写入的高亮，合并的划线。

### 3 · 对话编排

这一层负责四件事：

1. **拼 prompt**：当前人格快照 + 中间件召回结果 + 本会话历史
2. **调模型**：唯一直接调对话模型生成回复的地方
3. **分发回复**：网页端打进对话窗口；桌面端主窗口收流，经 IPC 转发给桌宠气泡。只维护一条 SSE
4. **送去写入**：回复结束后，用户这句和 AI 这句一起交给中间件 `ingest()`

### 4 · 记忆中间件

按 Omni-SimpleMem 三段式：选择性摄入 → 结构化存储 → 意图感知检索。六个环节：

| 环节 | 做什么 | 关键约束 |
|---|---|---|
| ① 筛选 | 留 / 丢 / 拿不准，每次判断带分数和理由 | **只筛被动采集**；主动输入跳过筛选 |
| ② 压缩 | 拆成自包含事实，代词解析，时间绝对化 | 主动输入也压缩；日记随笔另出一段摘要 |
| ③ 合成 | 同义合并，旧事实作废 | 写 `valid_to` 与 `superseded_by`，不物理删除 |
| ④ 检索规划 | 按意思 / 按字面 / 按标签，计划器选路径与深度 | 先查热，未命中再下探冷 |
| ⑤ 冷热调度 | 按访问频率与时效迁移 | 30 天未命中降冷；冷条目命中即整体回热 |
| ⑥ 性格沉淀 | 周期归纳相处特征，写回冷存储性格档案 | **读原始会话记录，不读记忆库**——压缩会丢语气 |

对外只暴露 `MemoryFacade` 五个方法（见 CONTRACTS.md）。

**事件总线**：每个环节的判断都以事件外发（filter / write / merge / recall），进 SSE 广播和 SQLite 归档。这是「让记忆看得见」的数据源。

### 5 · 存储

| 存什么 | 引擎 | 位置 |
|---|---|---|
| 热存储：近 30 天事实、当前待办、活跃话题、当前人格快照 | LanceDB 常驻索引表，三层索引全建 | `data/lance/hot` |
| 冷存储：全量历史与作废版本、相册摘要、日记摘要、性格档案 | LanceDB 归档表，仅摘要索引 | `data/lance/cold` |
| 相册原图、随笔与日记全文、音频片段 | 磁盘文件，冷存储里存指针 | `data/blobs/` |
| 会话记录、消息、用户可见的记忆分层、事件日志、设置、供应商配置、运行指标 | SQLite | `data/qiuqiu.db` |

分层依据是访问频率与时效，不是内容类型。

### 6 · 模型

统一适配接口，上层不感知具体供应商。

| 能力 | 默认实现 | 调用方 | 成本 |
|---|---|---|---|
| Chat | DeepSeek `deepseek-v4-flash` | 编排（生成回复）· 中间件（压缩、合成、规划、性格归纳） | 远程，按 token |
| Vision | DeepSeek `deepseek-v4-flash-vision-exp` | 中间件（图片 → 描述） | 远程，同一个 key |
| ASR | sherpa-onnx + SenseVoice int8 | 输入层（语音 → 文字），流式 | 本地，免费 |
| VAD | silero-vad | 输入层（静音与噪音过滤） | 本地，免费 |
| TTS | edge-tts（demo）/ 火山引擎（正式） | 编排（回复 → 语音 → 口型包络） | demo 免费，正式按量 |
| Image Gen | Seedream（可选） | 编排（「画一张」场景） | 远程，按张 |
| RealtimeVoice | 豆包端到端实时语音（可选） | 编排（语音直进直出，替代 ASR→Chat→TTS 链） | 远程，按音频 token |

### 语音链路的两种方案

**级联（默认）**：VAD → ASR → Chat → TTS，四段各自流式。全本地零成本（Chat 除外），但延迟叠加约 2–3 秒，不能打断，语气在转文字时丢失。适合 demo 与文字为主的场景。

**端到端（可选）**：`RealtimeVoice` 适配器，音频直进直出，延迟几百毫秒，支持打断，保留语气。记忆与人格照样以文本注入系统提示；模型同时返回输入与输出的文字转写，供写入记忆。口型直接吃输出音频的包络。默认实现豆包端到端实时语音，按音频 token 计费。

两种方案在 `.env` 里 `VOICE_MODE=cascade|realtime` 切换，编排按模式选路，记忆中间件不感知差异。

### 7 · 人格

三段，合成顺序：**预设打底 → 相处覆盖 → 边界否决**。

| 段 | 内容 | 存哪 | 可变性 |
|---|---|---|---|
| 安全边界 | 不模拟恋爱关系、不诱导依赖、不替代医疗法律心理建议 | 代码常量 | 不可关闭 |
| 人格预设 | 热情 / 安静 / 可爱 / 毒舌 四选一，或手调四个滑块，或不设 | SQLite `settings` | 用户可换可清空 |
| 相处性格 | 称呼习惯、玩笑尺度、话题偏好、回应长度 | 冷存储性格档案 | 性格沉淀周期更新 |
| 当前人格 | 上三者的合成缓存 | 热存储快照 | 预设改动或沉淀完成后重算 |

**「不设」是真空**：不往 prompt 里注任何滑块值，模型用默认行为，性格完全由相处长出来。

四个滑块：主动性（多久主动开话题）、话量（回应长度）、情绪浓度（感叹号与语气词）、玩笑尺度（能否拆台调侃）。预设是滑块的快捷方式，选完还能手调。

### 8 · 输入

两条路径，性质不同：

**主动输入**——用户打字、说话、传图、写日记，从界面进来，经编排到中间件。**跳过筛选，仍压缩。** 用户按了发送，内容是他的表达，不该被系统判断价值。

**被动采集**——常开麦克风的环境语音、摄像头画面。设备自己在采，不经界面，直连中间件。**必须筛。** 99% 是噪音。

AI 的回复走主动这一路。

## 一次对话的完整链路

1. 界面：用户说话，送到编排；状态机本地进「想」，不等后端
2. 编排 → 中间件：发检索请求
3. 中间件：检索规划选路径，先查热；未命中且涉及久远内容时下探冷，命中的冷条目整体回热
4. 编排：读热存储里的当前人格快照，与召回结果、会话历史拼成 prompt
5. 模型：生成回复，流式返回编排
6. 编排 → 界面：分发流式回复；桌面端主窗口收流后 IPC 转发给桌宠气泡
7. 界面：状态机进「说」，气泡逐字显示，有 TTS 时驱动口型
8. 编排 → 中间件：回复结束后，用户这句和 AI 这句一起送去写入
9. 中间件：主动输入跳过筛选 → 压缩 → 合成 → 写入热存储
10. 事件总线：write / merge 事件外发，侧栏追加，丘丘切表情
11. 中间件：达到周期阈值时触发性格沉淀，读 SQLite 原始会话，归纳后写回冷存储，触发人格快照重算

## 关键设计决策

**状态切换不走后端。** 首字到达就要立刻切「说」，多绕一趟服务端表情会比文字慢半拍。桌面端走 IPC，网页端走前端事件总线。

**当前人格用缓存，不每次合成。** 合成要读三处、做覆盖裁决，放在请求路径上拖慢首字延迟。

**主动输入不筛选。** 筛选器的存在是为了处理被动采集的噪音。用户主动说的，哪怕像废话，也是他的表达。

**性格沉淀读原始会话。** 「称呼习惯、玩笑尺度」是风格，压缩成事实之后语气就没了。

**桌面端只维护一条 SSE。** 主窗口收流，IPC 转发桌宠窗口。避免两个渲染进程各自重连时状态不一致。

**AI 的回复也进记忆。** 它说的承诺、建议，不记就丢了。

## 约束

**授权**
- 丘丘视觉形象：非商业。转产品必须替换
- Emotion Ball 引擎与表情数据：非商业免费，商业需授权
- SimpleMem：MIT
- SenseVoice / silero-vad / sherpa-onnx：开源可商用
- edge-tts：逆向 Edge 朗读接口的非官方用法，**demo 可用，不得用于产品**

**隐私**
- 所有记忆数据本地存储，不上传
- 唯一出网的是模型调用（DeepSeek、可选的 Seedream 和火山 TTS）
- 被动采集的原始音频只存指针，处理完即可删除

**成本**
- 语音识别、VAD 全本地，零成本
- 图片理解与对话共用一个 DeepSeek key
- 中间件调模型的次数是主要开销：一条输入至少两次（压缩 + 合成），检索规划一次，性格沉淀按周期

**平台**
- 开发在 macOS，目标平台 macOS + Windows
- Electron 透明置顶窗口在两个平台行为不同，需各自验证
- SenseVoice int8 模型约 200MB，首次运行下载
