AI 桌宠 · 系统架构

人格 · 界面 · 对话编排 · 记忆中间件 · 冷热存储 · 主动输入与被动采集

01系统全景

对话编排是新加的组件：拼 prompt、调模型、分发回复、把用户说的和 AI 说的都送去写入。人格注入的目标从界面层改到编排；界面与编排之间补了用户输入的下行线；事件总线单独成块，只传信号。

02对话编排 · 之前没有归属的四件事

动作输入输出说明
拼 prompt当前人格快照 + 中间件召回结果 + 本会话历史一份完整的模型请求人格在这里注入，不在界面层
调模型上一步的 prompt流式回复唯一直接调对话模型生成回复的地方
分发回复流式回复对话窗口 + 桌宠气泡桌面端：主窗口收流，经 IPC 转发给桌宠窗口，只维护一条 SSE
送去写入用户这句话 + AI 这句回复交给中间件 ingest两者都记。AI 说的承诺、建议，不记就丢了

桌面端的两个渲染进程共享一份流，实现上是主窗口拿到每个 delta 后经 IPC 转发给桌宠窗口——不让桌宠自己再开一条 SSE，避免断线重连时两边状态不一致。

03人格的三段结构

安全边界人格预设相处性格
内容不模拟恋爱关系、不诱导依赖、不替代医疗法律心理建议四个预设任选，或手调四个滑块，或不设称呼习惯、玩笑尺度、话题偏好、回应长度
来源产品硬性规则首次使用时用户选择，之后可改相处过程中归纳，写入冷存储
可变性不可关闭、不可绕过用户可换可清空随使用演化，用户可查看可重置
合成顺序预设打底 → 相处覆盖 → 边界否决。预设只是起点，相处得越久它的影子越淡；边界不贡献语气，只做否决

四个预设与四个滑块

预设是四个滑块的快捷方式——选预设等于一次性把滑块拨到某个组合，选完还能继续手调。相处性格会逐步覆盖这些初始值。

预设主动性话量情绪浓度玩笑尺度适合
热情高多高中想被陪着说话，怕冷场
安静低少低低怕被打扰，需要时才开口
可爱中中高高要轻松感，能软化情绪
毒舌高中中很高觉得一味温柔太腻
不设真空。不往 prompt 里注任何滑块值，模型用默认行为让它自己长出性格

四个滑块的含义：主动性决定它多久主动开一次话题；话量决定回应长度；情绪浓度决定用不用感叹号、语气词；玩笑尺度决定能不能拆台和调侃。安全边界与滑块无关——毒舌拉满也不会突破那三条。

不设预设这条路

「不设」是真空，不是「全居中」：prompt 里不出现任何滑块描述，模型按自己的默认行为回应。这时当前人格只剩安全边界和相处性格，而相处性格一开始是空的——所以最初它是一个没有语气倾向的中性回应者，性格完全从后面的相处里长出来。

选了预设不设预设
第一次对话已经有明确语气，符合所选人格模型默认行为，不带倾向
性格来源预设打底，相处逐步覆盖全部来自相处沉淀
收敛速度立刻可用需要一段时间才有辨识度
适合谁想要一个设定好的角色想要一个长成自己样子的伙伴
风险预设与用户期待不符时要手动换，或等相处覆盖早期体验平淡，可能留不住人

04性格沉淀读什么

性格沉淀归纳的是「称呼习惯、玩笑尺度、话题偏好、回应长度」——这些是对话的风格，不是事实。压缩步骤会把「我叫赵宁，我喜欢美式」变成「用户名字是赵宁」，语气在这一步就没了。所以性格沉淀读原始会话记录，不读记忆库。

项说明
触发周期任务。累积若干轮对话后跑一次，不在请求路径上
输入SQLite 里最近 N 轮的原始会话记录（用户与 AI 双方的原话）
处理调对话模型归纳四个维度的当前值，与上一版性格档案做增量合并
输出写回冷存储「性格档案」，触发当前人格快照重算
用户可见记忆库页面能看到归纳结果，可重置

05界面层收到的两路数据

路径传什么谁消费怎么用

状态切换那一路刻意不走后端——首字到达就要立刻切「说」，多绕一趟服务端会让表情比文字慢半拍。

06人格数据存在哪

段存储位置性质什么时候写
安全边界代码常量，不入库产品硬性规则随版本发布
人格预设SQLite settings 表用户配置，不是记忆用户选择或改动时
相处性格冷存储「性格档案」归纳产物每累积若干轮对话，性格沉淀跑一次
当前人格热存储「当前人格快照」三者的合成缓存预设改动或性格沉淀完成后重算

每次对话直接读热存储里的快照，不重新合成——合成要读三处、还要做覆盖裁决，放在请求路径上会拖慢首字延迟。

07冷热分层规则

热存储冷存储
引擎LanceDB 常驻索引表LanceDB 归档表 + 相册原图、随笔全文落磁盘文件
装什么近 30 天事实、当前待办、活跃话题、人格快照全量历史事实与作废版本、相册原图、随笔、日记、历史待办、性格档案
索引向量 + 关键词 + 标签三层全建仅摘要索引，原文与原图按需取
进入新写入，或冷条目被命中后整体回热热存储中 30 天未命中的条目降级
延迟毫秒级可接受一次加载开销
写入时机实时，事实一压缩完就写三种：每日定时扫描把 30 天未命中的降冷；相册原图与随笔全文写入时直落；性格档案每累积若干轮对话归纳一次后写回

会话记录、用户可见的记忆分层、事件日志、设置，这些不是记忆事实，放 SQLite。分层依据是访问频率与时效，不是内容类型——同一个相册里，本周的照片在热、三年前的在冷。一旦被问起就整体回热，避免同一话题反复穿透到冷存储。

08三种输入的差别

输入从哪进来筛选压缩原始数据
文字 · 对话（用户与 AI 双方）界面输入条 → 编排 → 中间件跳过拆成自包含事实会话记录入 SQLite
文字 · 日记随笔界面编辑器 → 中间件跳过拆事实 + 另出一段摘要全文落磁盘，摘要入冷存储索引
实时语音常开麦克风，设备被动采集能量阈值 + 语音活动检测转写后同对话处理音频指针入冷存储
图片上传为主动，摄像头为被动被动才筛：画面变化度比对视觉描述压缩成事实原图入冷存储相册

「不筛选」不等于「原样存」。主动输入跳过的是①筛选这一步，②压缩照做——「我叫赵宁，我喜欢美式咖啡。用一句话介绍你自己。」这句里的指令部分仍然会被剔掉。区别在于筛选器不会因为它「像废话」就整条丢弃。

09记忆事件到角色表现

事件侧栏显示角色表现
filter · reject灰色行 + 丢弃理由无反应，维持闲置
filter · uncertain黄色行 + 分数疑惑表情，短暂歪头
write高亮行 + 拆出的事实记忆气泡浮出，开心表情
merge旧条目划线 + 新条目旧气泡划掉，新气泡浮出
recall命中条目 + 走的路径星星眼，气泡标注引用条数

10一次对话的完整链路

#发生在动作
1界面用户说话，桌面端走内联输入条，网页端走对话窗口，送到编排
2界面状态机进「想」，缓慢歪头（本地，不等后端）
3编排向中间件发检索请求
4中间件检索规划选路径，先查热存储；未命中且问题涉及久远内容时下探冷存储，命中的冷条目整体回热
5编排读热存储里的当前人格快照，与召回结果、会话历史一起拼成 prompt
6模型层生成回复，流式返回给编排
7编排 → 界面分发流式回复：网页端进对话窗口；桌面端主窗口收流，IPC 转发给桌宠气泡
8界面状态机进「说」，气泡逐字显示，有语音合成时驱动口型
9编排 → 中间件回复结束后，把用户这句和 AI 这句一起送去写入
10中间件主动输入跳过筛选 → 压缩 → 合成 → 写入热存储
11事件总线write / merge 事件外发，侧栏追加，角色切表情
12中间件达到周期阈值时触发性格沉淀：读 SQLite 里的原始会话，归纳后写回冷存储，触发人格快照重算
